- 交互点累计：约 **350 次**；**闪退 0 次**
- 结论：**未发现闪退**；共发现并修复 **8 个缺陷**（3 个高危），汉化残留只剩品牌名 `OpenSPH`

## 二、缺陷清单（8 个，全部已修复并复验）

### D1（高）整数输入无校验，可写入 1 亿粒子
- 现象：把「粒子数」输入 `999999999`，内核收到 `particles.count = 999999999`
- 根因：`applySetting` 直接透传字符串，无范围校验；且输入框内容不会自动清空，导致追加（`10000` + `5000` = `100005000`）
- 修复：新增 `sanitizeNumeric()`——粒子类钳到 1–200 万、迭代类 0–100 万、其余 ±10 亿；非法输入拒绝并提示
- 证据：修复后输入 `999999999` → 日志 `set key=particles.count type=int value=2000000`

### D2（高）浮点输入丢小数点
- 现象：半径输入 `7.5`，内核收到 `body.radius = 75`
- 根因：`InputType.Number` 不接受小数点
- 修复：浮点行改用 `InputType.NUMBER_DECIMAL`，并限制量级 ±1e12、最多 6 位小数
- 证据：修复后 `set key=body.radius type=float value=7.5`

### D3（高）向量 / 区间分量编辑不提交
- 现象：「尺寸」第一分量改成 12，界面变化但内核无写入
- 根因：提交依赖 `onEditChange(false)` / `onSubmit`，在触摸输入的多输入行里不触发
- 修复：改为**输入防抖 700ms 自动提交**（`scheduleCommit`），并按 `key#idx` 分别暂存
- 证据：`set key=body.dimensions type=vector value=12,10,10`

### D4（中）星系初态 17 项参数未翻译
- 项：Bulge cutoff/mass/particle count/scale length、Disk mass/particle count/radial cutoff/radial scale/vertical cutoff/vertical scale、Halo cutoff/gamma/mass/particle count/scale length、Particle radius、Toomre Q parameter
- 修复：补入 `SETTING_LABELS_EXTRA`（核球截断/核球质量/…/Toomre Q 参数）
- 证据：星系初态节点 101 条参数文本中，英文仅剩 `OpenSPH`

### D5（中）9 个枚举选项值未翻译
- `relaxing` / `stratified` / `murnaghan` / `polytropic` / `simplified tillotson` / `tait` / `tensor grady kipp` / `dust` / `ellipsoidal`
- 发现方式：导出内核设置 JSON → 提取全部 29 个枚举值 → 与映射表做差集（比截图逐个看可靠）
- 修复：补入 `ENUM_LABELS_EXTRA`（松弛/分层/Murnaghan 状态方程/…/椭球形）
- 证据：分布下拉实测显示「六角密排 / 立方 / 随机 / 松弛 / 分层」

### D6（中）录制预览模式导致「模式」按钮位移
- 现象：切到「录制预览」后，离线条目被隐藏，「模式」行上移 200+ px；切回时容易点空
- 修复：把「模式」行移到对话框最顶部（预设之前），位置恒定
- 证据：切换前后「模式」按钮恒在 y=782

### D7（低）默认实例名未翻译
- `unnamed sphere` / `unnamed body` / `unnamed mesh` / `unnamed galaxy ICs`
- 修复：`displayNameValue()` 做显示层翻译（**写回内核仍用原文**），前缀 `unnamed ` → 「未命名」
- 证据：属性面板「名称」显示「未命名球体」

### D8（低）画质选择无视觉反馈
- 现象：切换快速/标准/高，摘要行完全不变，用户无法确认是否生效
- 修复：摘要行追加画质，如 `1920 × 1080 · 30 fps · 120 帧 · 画质：标准`

## 三、测试过程中的 3 次自我误报（记录以示严谨）

| # | 误报 | 实际原因 |
|---|---|---|
| 1 | 「六个菜单只有视图能打开」 | 我的筛选条件写死 `x0 == 301`（那是视图面板坐标），其余面板横向位置不同 |
| 2 | 「导出对话框切录制模式后选项消失」 | 属设计（录制模式只有说明+开始录制），但我据此判断「按钮位移」为 bug 是对的（D6） |
| 3 | 「画布连线连不上」 | 测试配对错误：把「氢气（材料输出）」连到「多重合并（要粒子数据）」，内核按类型拒绝；换「生成整体天体 → 多重合并」后一次成功，日志 `target=3 best=1.4` → `连线 1` |

另有 1 次坐标误判：把「缩放 220%」当成缩放下限，实际是点到了 ＋；用 dumpLayout 精确坐标重测得到真实边界 40%–250%。

## 四、风险与建议（未修，需产品决策）

- **R1 鼠标右键**：右键被系统截获，只能点「⋯」。如需右键支持，需确认 2in1 上鼠标事件分发策略。
- **R2 系统级减少动效**：`@ohos.settings` 的 `ANIMATOR_DURATION_SCALE` / `TRANSITION_ANIMATION_SCALE` 自 **API 21 起标记废弃**（「该常量不支持使用」）。当前实现为应用内开关 + 持久化，全量动画时长归零（`durMs()` 门控，14 处 `.animation` + 23 处 `animateTo` 全覆盖，实测 `MOTION_SCALE=0 → durBase=0ms`）。
- **R3 导出无「另存为」**：保存直接写应用沙箱默认路径，用户不知道文件在哪、也无法选择位置。建议接入文件选择器（picker）。
- **R4 长时稳定性**：未做数小时 soak test；SPH 模拟长时间运行的内存增长未量化。
- **R5 渲染上限**：Canvas 路线已到顶（1333 点 ≈19ms/帧），当前量产方案为 C++ 侧光栅化（40000 点采样、1000×1000、5–12ms/帧）。内核 `RayMarcher`（CPU，wx-free）可提供自遮挡，但需约 200 行胶水（`ICamera`/`IColorizer`/`RenderParams`），未接入。
